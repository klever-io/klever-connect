# validator-create (Node.js)

Build, sign and (optionally) broadcast a `CreateValidator` transaction
(contractType 2) using an operator's hex private key and a pre-generated BLS
public key.

## Why

Klever validators are identified by a BLS public key generated by the node
software. To link that BLS key to an on-chain operator account — and declare
commission, delegation acceptance, and metadata — the operator must publish a
`CreateValidator` transaction signed by the operator's Ed25519 wallet.

This example is the second of three steps in the validator onboarding flow:

1. **Generate the BLS key off-chain** with the Klever node binary.
2. **Onboard / register the BLS key** through the network's process (genesis
   for mainnet/testnet, automatic for `local`).
3. **Run this example** to publish the on-chain CreateValidator transaction.

## Prerequisites

- An operator wallet (hex private key) holding enough KLV on the target network
  to cover the CreateValidator fee + the role's self-stake bond.
- A real, eligible BLS public key (96 bytes / 192 hex chars). On testnet this
  must already be onboarded; otherwise the chain will reject the transaction
  even though it is well-formed.
- Node.js >= 18.

## Configuration

Copy `.env.example` to `.env` and fill in:

| Variable | Required | Notes |
|---|---|---|
| `PRIVATE_KEY` | yes | Operator's Ed25519 private key, hex (no `0x`). |
| `BLS_PUBLIC_KEY` | yes | Validator BLS pubkey, hex. 192 chars typical. |
| `REWARD_ADDRESS` | no | Defaults to operator address. |
| `CAN_DELEGATE` | no | `true` / `false`. Default `true`. |
| `COMMISSION` | no | 0–10000 (basis points × 100). Default `500` (5%). |
| `MAX_DELEGATION_AMOUNT` | no | Human-readable KLV; converted via `parseKLV`. |
| `VALIDATOR_NAME` | no | UTF-8 display name. |
| `KLV_NETWORK` | no | `mainnet` / `testnet` / `devnet` / `local`. |
| `DRY_RUN` | no | `true` (default) builds + signs without broadcasting. |

## Run

```bash
npm install
npm start
```

The script prints the assembled request, the truncated signed-tx hex, and
either skips broadcast (DRY_RUN) or shows the broadcast tx hash.

## Tests

```bash
npm test               # mocked unit test (CI-safe)
npm run test:testnet   # live testnet — requires PRIVATE_KEY + BLS_PUBLIC_KEY
```

## Gotchas

- A well-formed transaction can still fail at chain-level if the BLS key is not
  registered. Always verify on the explorer.
- The operator account needs sufficient KLV to bond as self-stake. Faucet
  the address first via `provider.requestTestKLV(address)` (testnet only).
- `commission` is encoded as integer basis-points × 100 (`500` = 5.00%). The
  chain rejects values outside [0, 10000].
- Don't reuse a real validator's BLS key for testing — the second
  CreateValidator with the same BLS will be rejected by consensus.
